# Рабочие правила ServicePulse

Перед изменениями прочитай docs/requirements.md, docs/architecture.md и docs/progress.md.
Работай проверяемыми шагами: inspect, implement, test, review, document, commit.
Backend, frontend и worker остаются отдельными; PostgreSQL — источник правды.
Не выдумывай результаты тестов, даты, commits, метрики и завершённые требования.
Фиксируй реальные команды и результаты в docs/development-log.md, обновляй progress.md.
Используй feature branches и Conventional Commits; не меняй даты и общую историю.
Спроси владельца перед новым PR, merge, публичной публикацией, заменой архитектуры,
разрушением данных и действиями с настоящими credentials. Локальные test credentials одноразовые.
19 октября 2026 владелец разрешил GitHub uploads завершённых проверенных этапов.
21 октября 2026 владелец явно разрешил сделать репозиторий публичным; видимость изменена и проверена.
Репозиторий: https://github.com/azimkhanrazdva/servicepulse. Не меняй видимость снова без разрешения.
После проверки делай обычный push настоящих commits; незавершённый этап остаётся локальным.
Нельзя force-push; разрешение upload не разрешает автоматически PR/merge/смену visibility.
Не помещай секреты в Git; private HTTP targets запрещены, кроме явных узких test exceptions.
Сохраняй пропуски наблюдений: отсутствие проверки не означает failed check.
Не добавляй декоративные кнопки или вымышленные данные; незавершённое обозначай честно.
Запускай релевантные tests/lint/typecheck/build; NOT VERIFIED не является PASS.
Не начинай следующий этап при критическом провале текущего; завершай checkpoint для владельца.
Текущий язык UI и документации русский; API, команды, file names и код на английском.
Подлинные исходные промпты и raw artifacts не переписывать задним числом ради перевода.
Письмо работодателю не отправлять; volumes и пользовательские данные не удалять.
Основной итог и оставшиеся действия: docs/OWNER_FINAL_REPORT_RU.md.
