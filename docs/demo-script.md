# Демонстрация ServicePulse за 8–10 минут

Начните с [README](../README.md). Откройте управление на 8080 и Mailpit на 8025. Используйте свой демонстрационный monitor `acceptance-demo` с URL `http://simulator:8001/target/acceptance-demo`, интервалом 30 с, таймаутом 2 с и порогом 2. Исключение private origin разрешено только явно заданному simulator. Создайте группу с локальным адресом `reviewer@example.test`.

| Время | Действие | Ожидаемый результат |
|---|---|---|
| 0–2 мин | Два окна управления; создать monitor и группу | Настройки сохранены, первый реальный HTTP 200 даёт UP, оба клиента обновляются |
| 2–4 мин | Simulator 500, две завершённые проверки, затем ещё ошибка и восстановление 200 | Первая ошибка не подтверждает падение; затем один incident и одно DOWN; повторная ошибка не дублирует письмо; успех закрывает incident и даёт RECOVERY |
| 4–6 мин | Активное окно обслуживания monitor или группы; повторить падение | Наблюдения и статус продолжаются, письма подавлены; после конца окна продолжающееся падение уведомляется без фиктивного CheckResult |
| 6–8 мин | Явно опубликовать monitor и отдельно историю; открыть два окна public на 8081; отозвать публикацию | Видны только разрешённые данные, SSE обновляется; после отзыва сервис исчезает в обоих окнах |
| 8–10 мин | Посмотреть 24 ч/7 д/30 д, покрытие и график; pause/resume; restart | Пропуски не считаются DOWN, настройки и история сохраняются; после resume появляется настоящее наблюдение |

```powershell
python scripts/simulator_control.py acceptance-demo --status 500
python scripts/simulator_control.py acceptance-demo --status 200
python scripts/simulator_control.py acceptance-demo --delay 10
python scripts/simulator_control.py acceptance-demo --delay 0
docker compose restart backend worker dispatcher
```

Новый ручной запуск выполняйте после завершения предыдущего: API409 при занятом lease корректен. В формах время локальное, в базе UTC. Существующие Demo monitors не меняйте. `python scripts/seed.py` необязателен и создаёт настройки, а не наблюдения.

Корень public 8081 намеренно возвращает 404; открывайте `/status/<slug>`. Покажите низкое покрытие нового monitor рядом со 100% успешных наблюдений: это не месяц непрерывной доступности. Объясните ограничения SMTP, отсутствие auth в локальном управлении и измеренный месячный максимум 1180 мс. Нагрузочный эксперимент не нужно повторять во время короткой демонстрации.

Автоматизированный сценарий после подготовки npm/Chromium:

```powershell
cd frontend
npx playwright test e2e/release.spec.ts --workers=1
cd ..
python scripts/phase7_clean_checkout.py --ref codex/russian-submission
```

Clean harness использует отдельный Compose project и новую базу на портах 28000/28080/28081/28025; volumes сохраняются. Скрипты пишут штатные имена reports: сегодняшние результаты дополнительно сохранены как `ru-*`, исторические файлы восстановлены.
